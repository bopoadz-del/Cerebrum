# 2025-01-21

## Chat Context Routing Fix

**Problem Identified:**
PDF, Audio (voice), and Image processing endpoints (`/documents/batch/process`, `/documents/transcribe`) were NOT indexing extracted content to ChromaDB. This meant users couldn't search processed files in text chat.

**User Decision:**
Chose Option B (frontend approach) over Option A (backend modification).

**Implementation:**
Updated 3 frontend pages to auto-index extracted text after processing:

1. **PdfPage.tsx** - After OCR extraction, creates text blob with metadata and POSTs to `/documents/upload/chat`
2. **AudioPage.tsx** - After transcription, indexes full transcription with duration/language metadata
3. **ImagePage.tsx** - After OCR, indexes extracted text with classification/entities

**Features Added:**
- Auto-indexing on successful processing
- Manual "Index to Chat" button for retry
- "Searchable in chat" badge when indexed
- Helper text suggesting chat queries

**Commit:** `82ad79e` - "Auto-index PDF/Audio/Image to chat after processing - searchable in text chat"

## Endpoints Reference

**Chat-connected endpoints:**
- `POST /api/v1/agent/v2/execute` - Main chat
- `POST /api/v1/documents/upload/chat` - File indexing (used by all file types now)
- `POST /api/v1/documents/batch/process` - PDF/Image OCR (now chains to upload/chat)
- `POST /api/v1/documents/transcribe` - Audio transcription (now chains to upload/chat)

**Result:** All processed content (PDF text, audio transcripts, image OCR) is now searchable in text chat via ChromaDB vector search.
